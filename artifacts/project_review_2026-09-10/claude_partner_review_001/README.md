## Direct PPO: real quiet chatter, no proven reset or optimizer defect

The [narrow final audit](claude_fable_ppo_audit_003/result.json) followed a broad worker that exhausted two output limits without a deliverable. Its [independent full-pilot review](direct_omni_claude003_independent_review_001/README.md) verifies both actual50-update campaigns. Parent reset calls the new command sampler; exact quiet rows remain zero, observed eligible plateaus redraw and all16 bearing bins/both yaw signs appear. Missing redraw is not a discovered bug.

Quiet target chatter is directly measured: roughly87.5% of joint/control deltas hit the0.04 rad limiter in both final stop traces. CAPS temporal loss changes little. Its aggregate loss is not a quiet-only95th percentile, and scalar loss magnitudes do not establish gradient balance or prove impossibility within50 updates. About68.34% of valid training pairs are already quiet, so there is no demonstrated omission of quiet examples. The next [bounded proposal](direct_omni_quiet_priority_proposal_001/README.md) increases only the exact-zero-command temporal priority and adds gradient/KL diagnostics; it is an experiment, not a missing-mask or learning-rate repair. Its frozen proposal mistakenly names `NEXT_RUNS.md`; actual integration uses `docs/NEXT_RUNS.md`.

The earlier [architecture reconsideration](claude_fable_architecture_003/result.json) is paired with [independent checks](claude_fable_architecture_independent_001/README.md). The actual diagnostic episode is90 seconds, with no timeout truncations; XYZW→WXYZ conversion matches independent quaternion calculations; every scored quiet command is zero; target increments are genuinely nonzero. These checks reject proposed setup explanations for the quiet failures. Standing admission does not itself prove every controller can remain quiet. No physics, observation, acceptance gate or checkpoint lineage changes follow from these reviews.

## Terrain: implement verified transport fixes and explicit runtime bridges

Read the [reviewer synthesis](claude_fable_terrain_001/SYNTHESIS.md), then the [complete final partner response](claude_fable_terrain_001/CLAUDE_REVIEW.md). The latter preserves two consecutive final text chunks; the CLI’s final result field alone contained only the second. The [independent CPU counterexamples](claude_fable_terrain_independent_checks_001/README.md) reproduce late old samples replacing newer ones under a custom jitter configuration, inference-created persistent storage breaking a later selective reset, and negative-age acceptance after a clock rewind. These are narrow existing transport seams; they do not mean an already-deployed terrain policy failed. A versioned successor is prepared separately.

Useful architecture work is source-bound course placement/reset, terrain-relative geometry/rewards, causal sensor/map bridging and a strict actor input boundary. Rejected or revised suggestions include swapping median fusion for mean as if equivalent; treating reset lift as support reward height; requiring the entire course inside a rolling map; ignoring rate/position disagreement outside energy calculations; inventing a safe return-to-liftoff abort; and relaxing the250 ms sensing lease. Actor architecture, terrain envelope, runtime integration and physical qualification remain open. The already-admitted48 fixtures prove geometry/probes, not complete walking.
