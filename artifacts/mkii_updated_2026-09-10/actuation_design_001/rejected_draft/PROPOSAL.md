# Canonical Phase B: shortest useful route to provisional scratch PPO

**Decision requested:** adopt a new canonical, explicitly provisional simulation actuator contract after the completed native003 import is audited. Run one small floating-root coordinate/effort experiment, then neutral standing under the declared servo, then a fresh two-update PPO smoke. Hardware identification remains required for transfer, not for these bounded simulation experiments. Nothing here authorizes a GPU launch or admits a policy.

All work uses the selected **7.466088235 kg, 19-body, 18-direct-joint** model. Exact URDF/model/USD and nine dependency hashes are in `INPUTS.json`. No old asset, checkpoint, action order, four-bar conversion, stand angles, phase controller or old environment class is reused.

## What can be chosen now

The source-bound CPU study makes CAD zero a credible first stance candidate. Transforming all 153 authored collision meshes gives a plate height of **0.076611091 m at first toe touch**, or **0.081611091 m with 5 mm reset clearance**. The six toe minima differ by only **0.703 micrometres**. Non-tibia collision geometry is at least **71.611 mm** above the plane. The material contact vertices are at approximately **tibia-local +X=0.130 m**, not the old +Y sphere. These are mesh extrema, not cooked SDF contact measurements.

An ideal six-vertical-force static solve balances the exact gravity load and moments with about **12.207 N per foot** and a worst required joint holding torque of **0.581644 N·m**. Independent force/moment and finite-difference virtual-work checks pass. The LP assumes nearly coplanar point supports and freely distributable normal loads; it proves neither that a PD servo realizes those loads nor that native contacts are stable. There is consequently no reason to begin with an expensive stance sweep or a mandatory five-support scripted gait.

## First native experiment: coordinates and effort, without ground

Keep the floating root, all self-collision/collider settings and source-bound mesh cooking. Start cold, with gravity zero, native position drives absent and raw torque control. Read native order and bind every array by name. Set articulation IDs with the actual SDK integer dtype; clone buffers outside inference mode before later mutation. Record reset before/after tensors and the first state, including the warmup boundary.

1. Run a 100 ms zero-input baseline. Check finite state, exact names/limits, no native errors and valid reset/history clocks. Measure root/joint motion and incoming joint reactions; zero-G is not a guarantee of zero motion or zero momentum when constraints/self-contacts initialize.
2. At reset boundaries only, independently set each named joint to +0.01 and −0.01 rad and check scalar position, all-link FK and the reset target/velocity buffers. Return to canonical state before the next case. Test +π scalar serialization/limits separately; do not step a near-limit combined pose and call it collision safe.
3. From a fresh baseline per case, apply ±0.02 N·m to each named joint for eight 2.5 ms substeps, then zero effort for 100 ms. Record every sample. Bound this experiment to |requested|≤0.1 N·m, |q−start|≤0.05 rad and |dq|≤2 rad/s; a breach ends the case with raw evidence. These are diagnostic bounds, not new motor limits. No PD gains are needed for this first experiment.
4. Bind the full floating-base generalized mass-matrix convention before using a response prediction. The instantaneous prediction is **M⁻¹[0₆;τ]**, not τ/Mjj; compare baseline-subtracted response and coupling, and retain constraint/reaction traces. A mismatch is diagnosed before closed-loop control. Total momentum is compared with its measured initial value and known external impulses, not assumed to start at zero. Do not equate raw root velocity with total momentum.

The actual 110.1.13 API exposes `set/get_dof_actuation_forces`, `get_dof_projected_joint_forces` and `get_link_incoming_joint_force`. The first reads the native actuation command; the second projects joint reaction; the third includes active/passive constraint wrench in the child joint frame. None is a measured hardware motor sensor, and constraint wrench need not equal the software command. Keep the three channels separate. Phase A returned native maximum effort zero: author and read back the new numerical bound, and experimentally establish whether that field limits explicit force input rather than assuming it does. Software clipping and delivered-command readback remain mandatory regardless.

The successful Phase A retained TGS with external-forces-every-iteration false and emitted the installed noisy-velocity warning. **Propose true for the new Phase B actuation source**, explicitly versioned and read back, with all other solver settings initially preserved. This is a deliberate new numerical setting, not a retroactive Phase A fix or a claim that the historical rate bias has a known cause. Record 400 Hz raw SDK rates and angle differences/dt separately; resolve material disagreement during the pulse experiment before using the rate as damping feedback. Do not quietly substitute a derived rate into old gates.

## One provisional servo, not a gain sweep

Proposed numerical model: 400 Hz explicit output-side PD torque, 50 Hz held position command, **1.6 N·m software cap**, no additional burst authority, and piecewise 48 V speed-envelope ceiling from the recorded manufacturer curve. Use `min(1.6, curve(|dq|))`, zero beyond its 480 rpm endpoint. Symmetric braking use is an explicit unvalidated approximation. Keep the source 50.26548 rad/s velocity ceiling; 480 rpm is no-load, not loaded performance. Do not multiply output torque/speed by the internal 7.75 ratio again.

The initial **Kp=12 N·m/rad** is a numerical proposal derived from 0.581644 N·m / a declared 0.05 rad static-error design budget, rounded upward. Set **Kd_j=2×0.8×sqrt(Kp×Ieff_j)**, with Ieff=1/(M⁻¹)jj from the zero-pose fixed-root rigid-link matrix: roughly 0.442 coxa, 0.246 femur, 0.106 tibia N·m·s/rad, recorded by exact name in `servo_candidate.json`. Zero extra armature/friction/latency are explicitly unmodeled values, not fitted estimates. The ideal semi-implicit linear fixed-root update has spectral radius 0.90898 at 2.5 ms. This is a useful rejection screen, **not native floating/contact/delayed/saturated stability proof**. A bounded native free response and gravity hold validate the candidate before training. A failed hold produces a specific stance/servo intervention, not a wider automated search.

The manufacturer distinguishes 5.5 N·m peak, 1.2 N·m continuous stall, cooling-dependent rotating ratings and 480 rpm no-load. **1.6 is a chosen numerical ceiling, not guaranteed continuous-stall capability.** At all speeds preserve raw demand, clipped command, native actuation input, actual clipping fraction, integrated mechanical work and time above 1.2 N·m, including startup. There is no synthetic temperature/current/cooldown model and no burst-budget reset pretending to be real cooling. Keep evaluations bounded to 20–48 s and label training as provisional simulation; the vendor stall table is not a certificate for repeated real episodes. [Manufacturer index](https://github.com/RobStride/Product_Information/blob/main/README.md), [English RS05 manual](https://github.com/RobStride/Product_Information/blob/main/Product%20Literature/RS05/RS05User%20Manual260713.pdf), and the previously byte-bound PDF review in `docs/RS05_SPEC_REVIEW.md` establish the distinctions, not the proposed gains.

## Gravity support and scratch integration

After the effort experiment passes, introduce a ground plane, gravity and the numerical servo in a new source. Start one cold neutral robot, then **32×1000 controls** if the one-row acquisition is valid. Read back contact positions into the named tibia frame and validate the rounded distal +X patch from actual mesh/SDF geometry; reject the old sphere/+Y classifier. Preserve nonfoot/shaft contact evidence, all 400 Hz requested/applied effort samples, clipping, finite state, no reset/termination standing gate and the existing saturation threshold. Root height is checked against this model's plane/contact geometry. Author every new geometry-specific threshold before dispatch; do not inherit the old 0.124 m height or 0.155 m +Y boundary.

Settled standing must retain all six distal supports and satisfy the original quiet and actuator acceptance criteria. Hardware limits and applied cap do not expand to make it pass. Acquisition completion, finite recoverable training failures and formal standing/quiet/evaluation admission remain distinct. Reset may initialize a simulated independent episode, but it must not erase another row's history or a terminal sample. A timeout bootstraps from the final pre-reset critic packet; a true terminal does not.

Then create one new model-bound direct-position task and **fresh actor/critic/normalizers/Adam**, with no checkpoint load path from C or four-bar runs. Encode actual executed target and limiter history, named joint state, command and contact/provenance validity. Keep raw SDK rate and interval-angle evidence distinct. Use a command-balanced stand/move/stop curriculum and no hand-prescribed gait/support count. Freeze observation/action version and exact finite target bounds before the smoke. First run **32×24×2 updates plus strict fresh reload**, then choose one bounded pilot size from actual canonical 153-SDF throughput and memory. Historical C 1024-env throughput is not a capacity proof for this asset. Hardware calibration and terrain/perception work continue independently.
