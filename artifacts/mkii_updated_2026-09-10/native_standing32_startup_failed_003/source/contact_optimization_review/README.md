The candidate changes only two classifier computations: cache unchanged per-body cap transform values within one call, and aggregate non-toe body forces in their original patch order instead of rescanning every patch for every sensor. It preserves every raw patch, including inactive records, their ordering, field values and per-patch classification. The cap arithmetic itself, local/body coordinate convention, returned force reductions, >1N predicates, normal tolerance, sensor/range/completeness rejection and all servo/clearance code remain unchanged. No contact decimation or summary-only logging is introduced.

Candidate output is exactly equal to the unchanged parent on all8,000 actual rows and93 synthetic replicated/grid-translated cases (31 actual strata at2,8,32). This checks array dtype, shape and bytes plus full patch JSON ordering/values. Independent Mac replay of the original Spark shape-local coordinates differs by at most2.78×10⁻¹⁷m; every other patch field and category matches. We therefore claim exact candidate-versus-parent parity on this CPU, not bit-identical cross-machine raw reconstruction. Synthetic replication is not native32 evidence.

The candidate's weighted32 classifier time is165.64s, about1.91× faster, making its measured classifier+unchanged clearance/JSON sum268.11s before the same unknown costs. This is a localCPU benchmark, not a promised Spark deadline.
