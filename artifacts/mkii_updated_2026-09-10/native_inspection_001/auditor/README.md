It does not mean the native inspection passed. An authentic failed campaign produces `terminal_outcome=authentic_terminal_failure` and `inspection_completed=false`; an audit error or inconsistent completion exits nonzero. A completed native state is replayed through the exact post-exit producer validator, including late native errors. Completed campaigns additionally require exact receipt equality, successful job/unit exits and the complete host post-exit payload seal. No physical admission or training is inferred from either outcome.

A failed startup with no recorded ID checks only the exact name and explicitly states that no ID absence was established; it never invents a second identity. Docker-daemon errors are unknown absence and reject. Restoration must name exactly the previously active timers, have a finite time after pause creation, and match the canonical pause/source and exact dispatched command. Current timer activation is not inferred from an old restoration receipt.

All run and pause payloads are recorded with SHA-256 and byte sizes, then fully hashed again to reject changing output. Failed native outputs are preserved and inventoried even when no successful seal exists. The audit reports its own validation errors as JSON and never changes the source, campaign or raw evidence.
