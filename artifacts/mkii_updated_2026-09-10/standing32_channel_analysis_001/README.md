# Native standing32: preserved force-channel analysis

The original 32-robot standing run remains rejected: **10/32 pass the combined gates, 22 lose required measured support and 8 fail SDK quiet-rate limits**. This bundle preserves the completed, read-only CPU analysis of that run. It adds no native execution, training admission or changed threshold.

The replay found 73 missing-foot events. In all 73, the detailed toe-patch force and the corresponding tibia floor-matrix force are both at or below the unchanged 1 N support threshold. There is no event where the detailed toe channel is low while the tibia matrix exceeds 1 N. This is agreement between two measured channels that may share a backend; it does not independently establish physical support loss or explain its cause. The tibia matrix also covers the whole link rather than proving distal contact.

The normal-force channels must not be read as total contact force: friction is a separate getter. In particular, horizontal floor-force-minus-momentum differences in the preserved diagnostic output are **not a complete force balance**. The original analyzer output and limitations are retained verbatim; this qualification prevents overinterpreting them.

The CPU replay checks all 3,686,400 recorded pre/post joint-angle scalar comparisons and reconstructs the selected 360 raw contact rows with the original FP32 force products and ordered FP64 sums. Its 576 joint/environment rate pairs still show differences between reported SDK velocity and interval angle change. Maximum RMS is 0.0675342 rad/s for 400 Hz SDK velocity and 0.0459572 rad/s for interval angle rate; these maxima occur on different joints. The largest absolute integrated SDK-minus-angle difference is 0.0386200 rad. Neither channel is treated as independent ground truth, and the original SDK gate is not replaced.

**Window definition:** the original standing report scores 800 control endpoints at 50 Hz over **16 seconds after 4 seconds of settling**. The diagnostic uses 6,400 substeps over that same 16-second interval, with FP64 accumulation. The original maximum SDK quiet RMS is 0.106079 rad/s. Different sampling and accumulation are explicit; this is not a comparison against a final 10-second score. Ten seconds is only the scorer's minimum required duration. See the unchanged report inside [actual/analysis.json](actual/analysis.json) and its source-bound audit in [source/inputs/audit.json](source/inputs/audit.json).

Recorded used slots peak at 2,641 against a recorded capacity of 32,768. Original native starts/counts and global backend occupancy were not exported, so these numbers do not prove that every internal reporting buffer stayed below capacity. Whole-body momentum and pose-difference calculations are diagnostic, with hidden constraints and FP32 differencing uncertainty. The earlier source003 comparison changes solver settings, instrumentation and batch state; it is not a controlled causal comparison.

## Included evidence and limits

- `source/` contains all 15 frozen analyzer payloads plus their exact freeze manifest. Its preparation-time statements remain historical; the separate execution receipt establishes this actual run.
- `actual/analysis.json` is the complete 22,361,724-byte result, SHA-256 `304bccb643f1be8ab95a41d98c85c985e7248652a208e20ac51b71006ff60231`. The execution completed with return code 0. Source transfer, operator code, stderr and final reservation readback are preserved.
- The analyzer verifies the 18 raw inputs it consumes and all 109 native source payloads before/after analysis. The full terminal audit binds **39 raw files / 5,019,294,627 bytes**. Those original raw files remain remote; this bundle does not provide a self-contained raw numerical replay. The other 21 files remain audit-bound, rather than being claimed as reread by this analyzer.
- `SUMMARY.json` is a reproducible compact extraction from the full result. `COPY_VERIFICATION.json` records every original-to-public copy. Source geometry, standing scorer, original failure and frozen preparation bytes are unchanged.
- The final operational readback verifies 31 user masks, the held queue lock and no CUDA compute process at its recorded timestamp. Eleven reload flags remain `yes` in the receipt. It reports zero native calls and mutations; it is a point-in-time check, not a permanent partition against arbitrary privileged work.
