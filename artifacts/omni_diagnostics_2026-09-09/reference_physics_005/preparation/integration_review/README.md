The motivation is actual004's nearly stationary standing poses with reported velocity integrals differing by up to9.706mm over16s, despite actual400Hz updates. The measured trace is byte-identical to003, and simple timing shifts/frame conversion do not explain the discrepancy. NVIDIA documents that constraint solver pose updates and reported velocities can differ because geometric and velocity errors are solved separately. Its TGS force timing option distributes external forces across internal solver iterations. See [PhysX5.6.1 solver documentation](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/docs/RigidBodyDynamics.html#solver-iterations) and the [steady-state discussion](https://nvidia-omniverse.github.io/PhysX/physx/5.8.0/docs/Simulation.html#tgs-steady-state-velocity-and-position-discrepancy). This motivates a controlled test; it does not establish which mechanism caused every measured error.
