# Bounded external device smoke host, version 2

This host prepares two short allocations: `replicas_1`, followed by `replicas_32` only if the first result and all immutable inputs pass. Each allocation runs exactly 264 controls: the original source009 200-control canonical startup/settling and 64 controls of the new tensor reference's zero-command hold. It loads no actor/checkpoint and starts no PPO or walking successor. GPU execution is owned by root; this preparation has launched nothing.

## Source and supervision

The host pins the exact 926-file source009 map, 18-file device adapter, 160-file observation005 bundle, completed009 campaign/standing/wave receipts and 550 admitted asset files. `validate_inputs(args)` is read-only and available before a forecasting pause. It also checks this host's complete freeze inventory, including `numeric_evidence.py`; the outer guard must pin this final freeze hash before import. Importing this host by path requires its parent directory on `sys.path` so the sibling reader can be found.

The supervisor is imported directly from the pinned source009 `launch_reference_physics_spark.py` (SHA `9ebabaf254cc77fabad7d4759cc80fc26d7efd3912ea84bd55304594c88ed561`). Its `run_owned`, GPU resource preflight, two locks, 90 s AppReady and 600 s phase deadlines, contact-overflow log checks and exact-identity cleanup are unchanged. Only its command callback is overridden, and it is restored on exit. No code assumes the GPU is free. Root supplies the outer bounded systemd dispatch, identified forecasting pause and restoration.

All source, admitted-run/assets, adapter and observation mounts are read-only. Each phase uses a separate owned container and output subdirectory. A failed/partial first phase prevents the second allocation; existing evidence is never deleted or resumed. The starting host freeze hash is recorded and checked again with source/input identities at phase boundaries and terminal exit.

## Result checks

A phase needs exact completed bridge identity, source/runtime integrity, 264 controls, 846/849 observations, no policy/Stage2 promotion, and the independent device-versus-source009 reader comparison. The 400 Hz observer must have exactly 2,113 samples, 264 completed controls, no errors, restored callback, unchanged gates and zero postsettle saturation. Requested/applied postsettle maxima must be finite and no greater than 1.6 N·m.

The standard-library reader accepts only complete numeric C-order NPY payloads of the declared shape and dtype; it never loads pickle/object arrays and needs no host NumPy installation. The host checks finite final actor/critic packets, preserved raw SDK dq, valid interval-angle history, final contact/terminal masks, all 264 sensor-clock validity rows, exact source-bound cache timestamps and zero observed cache age. The host independently reconstructs each row from the previous observed row using eight float32 additions of the float32 2.5 ms constant, so synchronized duplication or reordering of current/last/expected arrays cannot pass. The first observed epoch remains source-bound rather than assumed zero. It independently reads all substep requested/applied torques, checks postsettle interior peaks against the recorded maxima, and checks all physical sample times. The 64 timing rows must be finite and sequential.

`*_accepted.json` records hashes of the 12 expected output artifacts. These checks qualify a short device bridge only. They grant no fresh 10 s quiet admission, native velocity-fidelity claim, training throughput estimate or PPO permission. The underlying bridge retains original CPU telemetry copies and 400 Hz evidence inside the measured environment-step time.
